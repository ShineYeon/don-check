# 제품 요구사항

## 1. 문제 정의

사용자는 매월 여러 금융 상품 또는 계좌에서 자동이체되는 금액을 출금 전에 준비해야 한다. 출금일과 금액이 서로 다르고, 돈을 옮긴 행위 자체는 은행 앱 여러 곳에서 일어나므로 한 화면에서 준비 상태를 확인하기 어렵다.

일반 할 일 앱은 월별 반복과 알림은 제공하지만 다음 요구를 동시에 만족하기 어렵다.

- 이번 달 전체 준비 금액과 남은 금액을 한눈에 본다.
- 출금 전에 항목별로 알림을 받는다.
- 완료하지 않은 항목은 출금일 이후에도 다시 알려 준다.
- 앱을 열지 않고 알림, 위젯 또는 잠금 화면에서 체크한다.
- 한 번 체크한 항목은 현재 월급 주기에만 완료되고 다음 월급일에는 자동으로 다시 나타난다.
- 일반 알림 목록에 묻히지 않는 가시성 높은 표시가 필요하다.

DonCheck는 금융 거래를 수행하는 앱이 아니라, 사용자가 수동으로 수행한 입금 준비 상태를 기록하고 노출하는 앱이다.

## 2. 제품 목표

### 2.1 핵심 목표

- 월간 자동이체 준비 누락을 줄인다.
- 사용자가 현재 남은 금액과 미완료 개수를 즉시 알 수 있게 한다.
- 완료 처리에 필요한 동작 수를 최소화한다.
- 서버 없이 개인 기기에서 독립적으로 동작한다.
- 홈 화면보다 잠금 화면을 자주 보는 사용 패턴을 지원한다.

### 2.2 성공 기준

MVP 관점에서 다음 조건을 만족하면 핵심 플로가 동작한다고 본다.

1. 사용자가 항목을 추가하고 앱을 종료한 뒤 다시 열어도 데이터가 유지된다.
2. 출금일과 사전 알림일에 로컬 알림이 예약된다.
3. 앱, 위젯, 알림 액션 중 어느 경로로 완료해도 동일한 월급 주기 기록에 반영된다.
4. 월급일이 되면 이전 완료 기록을 훼손하지 않고 새 주기가 미완료로 표시된다.
5. Live Activity가 허용된 기기에서 체크리스트가 잠금 화면에 표시된다.
6. 모든 항목을 완료하면 해당 월의 불필요한 알림과 Live Activity가 정리된다.

## 3. 주요 사용자 시나리오

### 3.1 항목 등록

사용자는 `+` 버튼을 누르고 다음 정보를 입력한다.

- 이름: 예) 청약저축
- 금액: 예) 250,000원
- 매월 출금일: 예) 2일
- 알림 시각: 예) 오전 8시
- 사전 알림: 예) 1일 전
- 미완료 재알림: 예) 이후 3일

이름이 비어 있거나 금액이 0 이하이면 저장할 수 없다. 출금일은 1~31, 사전 알림은 0~14일, 재알림은 0~7일 범위다.

### 3.2 현재 주기 준비 상태 확인

메인 화면은 다음 정보를 보여 준다.

- 현재 연월
- 미완료 항목의 총 금액
- 완료 개수 / 전체 개수
- 진행률
- 항목별 금액, 출금일, 알림 시각, 완료 상태

### 3.3 완료 처리

사용자는 다음 경로에서 완료 처리할 수 있다.

- 앱 목록의 체크 버튼
- 홈 화면의 medium/large 위젯
- Live Activity의 잠금 화면 또는 Dynamic Island 확장 화면
- 전달된 로컬 알림의 `입금 완료` 액션

모든 항목에는 `입금 완료` 단계가 있다. 자동이체 후 실제 저축 반영까지 확인해야 하는 항목에는 `저축 완료` 단계가 추가되며 두 단계가 모두 끝나야 최종 완료다. 비자동이체 항목은 입금 완료만으로 최종 완료다.

완료 처리 후 저장소, 위젯, 배지, 향후 알림, Live Activity를 다시 동기화한다.

### 3.4 다음 월급 주기 전환

설정한 월급일을 말일 보정한 뒤 주말·동기화된 공휴일을 건너뛴 직전 영업일 00:00이 되면 앱은 별도 reset job을 실행하지 않는다. 화면이 주기 시작일 기반의 새 `cycleKey`를 사용하기 때문에 이전 완료 기록은 조회 대상에서 빠지고 모든 항목이 새 주기 기준 미완료로 나타난다.

## 4. 기능 요구사항

| ID | 요구사항 |
|---|---|
| FR-001 | 사용자는 저축 항목을 생성, 수정, 삭제할 수 있어야 한다. |
| FR-002 | 항목별 금액과 매월 출금일을 저장해야 한다. |
| FR-003 | 항목별 사전 알림과 재알림 횟수를 설정할 수 있어야 한다. |
| FR-004 | 완료 여부는 월급일 기준 주기별로 독립되어야 한다. |
| FR-005 | 현재 주기의 남은 금액과 완료 진행률을 계산해야 한다. |
| FR-006 | 앱을 열지 않고도 지원되는 시스템 UI에서 완료할 수 있어야 한다. |
| FR-007 | 완료된 항목의 현재 주기 pending/delivered 알림을 제거해야 한다. |
| FR-008 | 위젯과 앱은 동일한 데이터를 사용해야 한다. |
| FR-009 | Live Activity가 비활성화된 경우 사용자에게 원인을 알려야 한다. |
| FR-010 | 모든 항목이 완료되면 현재 및 예약 Live Activity를 종료해야 한다. |
| FR-011 | 사용자는 매월 월급일을 1~31 범위에서 설정할 수 있어야 한다. |
| FR-012 | 월급일이 없는 짧은 달에는 해당 월의 마지막 날을 주기 경계로 사용해야 한다. |
| FR-013 | 월급일 변경 시 위젯, 알림과 Live Activity를 새 주기로 다시 동기화해야 한다. |
| FR-014 | 사용자는 항목별로 자동이체 후 저축 완료 확인 필요 여부를 설정할 수 있어야 한다. |
| FR-015 | 자동이체 확인 항목은 입금 완료와 저축 완료를 독립적으로 기록해야 한다. |
| FR-016 | 비자동이체 항목은 입금 완료만으로, 자동이체 확인 항목은 두 단계 완료로 최종 완료를 계산해야 한다. |
| FR-017 | 단계별 알림 액션은 해당 단계의 알림만 정리해야 한다. |
| FR-018 | Dynamic Island compact 영역에서 DonCheck 식별자와 전체/입금/저축 집계를 제공해야 한다. |
| FR-019 | Dynamic Island 공간이 부족해도 축약 표시와 VoiceOver를 통해 집계 의미를 보존해야 한다. |
| FR-020 | 자동이체 확인 항목은 매월 자동이체일을 1~31 범위에서 설정해야 한다. |
| FR-021 | 월급일이 주말 또는 동기화한 공휴일이면 연속 휴일을 건너뛴 직전 영업일을 실제 월급일과 주기 경계로 사용해야 한다. |
| FR-022 | 입금 Live Activity는 실제 월급일 하루 전부터 입금 완료까지 표시 대상이어야 한다. |
| FR-023 | 저축 Live Activity는 영업일 보정된 실제 자동이체일 하루 전부터 저축 완료까지 표시 대상이어야 한다. |
| FR-024 | 자동이체일이 주말 또는 동기화한 공휴일이면 연속 휴일을 건너뛴 다음 영업일을 사용해야 한다. |
| FR-025 | 사용자는 iPhone의 구독 공휴일 캘린더를 명시적으로 동기화할 수 있어야 하며 동기화 결과는 앱과 extension이 공유해야 한다. |
| FR-026 | 공휴일 캘린더 접근이 없거나 대상 캘린더가 없으면 주말만으로 계산하고 사용자에게 동기화 실패 사유를 알려야 한다. |

## 5. 비기능 요구사항

### 5.1 개인정보

- 체크리스트 데이터는 기기 내부에만 저장한다.
- 사용자 계정이나 금융기관 인증을 요구하지 않는다.
- 계좌번호, 잔액, 거래 내역을 수집하지 않는다.
- 분석 또는 광고 목적의 제3자 SDK를 포함하지 않는다.

### 5.2 신뢰성

- 앱 프로세스와 widget extension 프로세스가 종료되어도 저장 데이터가 유지되어야 한다.
- 로컬 알림은 앱이 실행 중이지 않아도 시스템이 전달할 수 있도록 미리 예약한다.
- 시스템이 Live Activity를 거절해도 일반 알림과 앱 기능은 계속 동작해야 한다.

### 5.3 성능

- 데이터 규모는 개인용 체크리스트 수준을 가정한다.
- 저장 시 전체 `ChecklistData`를 JSON으로 인코딩하므로 수백~수천 항목 규모는 목표가 아니다.
- Live Activity content state의 시스템 크기 제한을 고려해 항목 수가 많은 경우 향후 payload 축약이 필요하다.

## 6. 명시적 비범위

현재 버전은 다음 기능을 제공하지 않는다.

- 실제 계좌 이체 또는 자동이체 실행
- Open Banking/금융기관 API 연동
- 자동 출금 성공 감지
- 여러 사용자 간 공유
- iCloud 동기화
- Android 또는 웹 클라이언트
- Apple 미리 알림 앱과의 양방향 동기화
- APNs 기반 무기한 Live Activity 갱신
- 월별 통계/차트/내보내기

## 7. 플랫폼 제약

- 일반 notification을 알림 목록 최상단에 영구 고정할 수 없다.
- Dynamic Island의 우선순위는 iOS가 결정한다.
- Live Activity는 사용자가 직접 제거할 수 있다.
- 한 Live Activity의 활성 시간과 전체 동시/예약 개수는 시스템 제한을 받는다.
- time-sensitive notification은 사용자가 앱별로 비활성화할 수 있다.

따라서 제품 문구는 "항상 고정"이나 "절대 누락되지 않음"을 보장해서는 안 된다. 현재 구현은 시스템이 허용하는 범위에서 가시성과 지속 시간을 최대화하는 전략이다.
